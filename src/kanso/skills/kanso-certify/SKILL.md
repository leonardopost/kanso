# kanso-certify

## Plan first (once per hypothesis)
1. `kanso cert plan <id> --json`. The `certify_plan` task class reads the hypothesis, the gate toolbox (each gate's `meaningful_when`, params and ranges — the toolbox has no defaults and no thresholds of its own), data availability, the construct, the trial count and the looks the hypothesis's lineage has already taken at its certification window (`inputs.looks`) — never research results — and returns the cert/paper/live gates, each with parameters chosen inside its ranges and a rationale, plus the gates it considered and excluded, with reasons. kanso validates the plan against the invariants (every required gate this version can run — the paper gates `paper_forward` and `forward_holdout` among them, each with both its parameters set — `min_duration` and `horizon_mult`, `resolve` and `min_fraction` — so a plan pinned before the second was required, or naming either without both, is refused with `--replan` — ≥1 cert gate, ≥1 paper gate, ≥1 live gate, params inside ranges, and — once the hypothesis's `n_trials`, every card it has, and the `prior_trials` its family declares tried outside kanso (an offline grid stated in `hypothesis.yaml`) reach two together — the deflation gate whose library file `deflates` its objective: `deflated_sharpe`, `deflated_contribution` or `deflated_edge`, with its threshold set at a value the planner chooses), retries once with the errors, and pins it at `certificates/<id>/plan.yaml`. A plan pinned without that gate, or with it and no threshold, is refused (exit 3, remedy `kanso cert plan <id> --replan`) from the second draw: by `cert plan` and `cert run` from the second card or the first behind a declared grid, and by `cert plan` already with no card behind a grid of two settings or more, where `cert run` has no card to certify (exit 2). A hypothesis scored on `wf_contribution_bps` or `wf_sharpe_net` carries `entry_timing` with `max_p` set in every plan, from the first and whatever the trial count, and never excludes it: the trades against the same trades circularly shifted by whole sessions, so a drift held is not credited as timing. A plan pinned without it is refused the same way; `max_p`, in `[0.01, 0.25]`, is the planner's, and `min_attainable_p` in its evidence, `1/(1 + draws)`, is the smallest `p` the window can resolve. A cert-stage gate this version has no implementation for is neither offered to the planner nor accepted from it, so it is absent from the toolbox and from the plan until its implementation ships. Without a configured model the step exits 2: there is no default plan by design.
2. Show the operator the plan as a two-column list: gate (with its parameters) → rationale, then the exclusions, then the `power` line: the edge the certification window resolves at 80% power and the probability `embargoed_window` passes at the research estimate and at zero, from the error the best card recorded (no line when it is zero). A window that resolves only an edge far above the one researched is worth saying out loud before `cert run` spends it. Then the `forward` line: how long the paper stage's forward window runs before `forward_holdout` first judges at the planned `resolve` (`days_to_judge`, `periods_to_judge`; `null` for a best at or too near zero to state a wait from — the gate judges the certified value, not research's) and its error after a year, from the same best card and research's selection-inflated value, so usually the shortest the wait can be — a certified value above research's makes the gate judge sooner. No version is marked `promotable` from this release on before that gate judges, so say this wait out loud too: it is the earliest a version of this hypothesis not already `promotable` can reach live capital. The plan is the agent's answer to "what would convince a reasonable person about *this* thesis" — it should look different for a 30-minute and a 3-month horizon.
3. To change it: `kanso cert plan <id> --replan` re-runs the planner on the same closed inputs and produces a new `plan_version`. Never edit `plan.yaml` by hand; the planner takes no free-text input by design.

## Run
4. `kanso cert run <id> [--sha S] --json` (default = `best`; `S` is any unique prefix of a card's `strategy_sha`; plans automatically if no plan exists). Runs the plan's cert gates on the embargoed certification window and the pinned data snapshot; under a `warmup` both windows are run warmed on the sessions before them, and the evidence gates read the certification window's own lags and volume. Writes `certificates/<id>/<sha7>-<n_trials>-p<plan_version>-e<engine version>.yaml` with the certified `strategy.py` beside it as `<sha7>.py`. Exit 2 if this `strategy_sha` was already certified under the same plan version **and** the same engine version — so after an engine upgrade, re-certifying an unchanged commit is a plain `cert run` with no replan. Exit 2 too, writing nothing, when the search behind the subject cannot be priced: two or more draws — cards that ran and traded, and the settings of a declared grid — but fewer than two cards scored under the subject's objective (a hypothesis re-pinned to another objective, its carried strategy certified as the first card under it, or the first card behind a declared grid — research further, then certify), or the subject was scored under an objective whose deflation gate the pinned plan does not carry (`--sha` of a card from before such a re-pin). The deflation's `trials` counts every card that ran and traded, under any objective, and the declared grid's settings, which its `prior_trials` gives apart — so `trials` can exceed the certificate's `n_trials`, which counts cards alone; `scored_trials` the cards its spread was read from.
5. `kanso cert show <id>`: verdict, then per gate `pass`, `evidence`, `skipped` (nothing to evaluate, e.g. no deployed strategies for `book_correlation`).
6. Report: verdict, failing gate ids with one number each from `evidence`, `n_trials`, and the certificate's `power.resolves`. Three lines maximum.
7. Pass → kanso auto-composes the strategy and deploys it to paper (skill `kanso-promote`); the plan's paper/live gates then govern promotion and demotion. Fail → status returns to `researching`; failing gates are fed back to the loop. `n_fail` consecutive fails → `failed` + inbox entry.

## Rules
- Never re-plan to make a certificate pass.
- A stall certifies only a best whose search correction — the plan's `deflated_sharpe`, `deflated_contribution` or `deflated_edge`, at its threshold — passes on research data. One it refuses is **spared**: no certification window is read, no certificate is written, nothing counts toward `n_fail`, and the hypothesis goes back to research. `kanso status --json` → `hypotheses[].last_stall.precheck` (and `kanso research run --json` → `stall.precheck`) names the gate, its `evidence` (`probability` against `min_probability` under `deflated_edge` and `deflated_contribution`, `dsr` against `min_dsr` under `deflated_sharpe`), and `measured` — whether the research window was run for it, not why. The lane runs nothing and reads the card's stored measurement, and its precheck is recorded only where it spared the stall — `false`, judged, refused, no `reason`. Where the lane could not judge, its reason is not recorded: the certification child is started and its precheck replaces the lane's. The child's is `true`, on the research window it ran, which it does at every stall the lane lets through, so every stall that certified says `true` — but one on a snapshot that cannot support a claim, where the child runs no window, writes a failing certificate and records a precheck that judged nothing, `false`, its `reason` saying so. The lane judges nothing on such a snapshot either, so a stall on one is never spared: its failing certificate counts toward `n_fail` like any other. `judged: false` with a `reason` spared nothing. `stall` in `kanso research run --json` is the stall that invocation ended on, and its `certificate` is set only when the best stands certified under the pin its stall judged it by, the pinned plan and the installed engine — `null` beside a spared stall, whatever an earlier plan or `hypothesis.yaml` certified. Report a spared stall as research that has not yet beaten its own search; `kanso cert run` by hand is never spared, and certifying a spared best anyway is the operator's call, not yours.
- Every certificate is a **look** at its certification window, counted over the hypothesis's lineage (every registered hypothesis joined to it by `derived_from`, siblings included) — pass or fail, after a replan or an engine upgrade too; one struck on a snapshot that cannot support a claim, and a spared stall, are none. The count judges nothing: every gate that judges, the search correction included, does so by the threshold the plan pins at every look, and so does a stall's precheck. A correction that skips — while fewer than two cards behind the subject ran and traded, among other cases — judges nothing and passes, so the lineage's chance of a false pass over its looks at one window is up to the sum of each look's complement of the threshold its correction judged it by, one for a look whose correction judged nothing, under a plan that carried none or because it skipped — `L × (1 − threshold)` only where all `L` judged by one threshold, never the threshold. Each certificate keeps its threshold among its correction's `params`, and a skip leaves them in place: read the gate's `skipped` before its threshold. `kanso status --json` → `hypotheses[].holdout_looks` gives the looks taken; a certificate's `holdout` (`cert show --json`, the `hold-out` line) its own look; a plan's `inputs.looks` those its planner was shown. Report a pass at a later look with its look beside it, never as a first look's pass. A replan does not reset the count, nor does a re-pin that keeps `derived_from` and a certification window sharing a day with the last; a re-pin onto a window sharing no day with it starts a new count once the subject is read there, and one that drops a `derived_from` link can split the lineage, taking the hypothesis's looks out of the others' count and theirs out of its own — say so when you report a count that moved. A card is certified on the window of the file the research run that carded it pinned, so a best carried across a re-pin that moved only the window is certified on — and counted at — the old window until a research run under the new file cards it again; `holdout_looks` counts where the best's next certificate reads, and `inputs.looks` where the next certificate of the card its plan was made for read — the best's, or the named card's where `cert run --sha` made the plan, so a plan `--sha` made at another window does not give the best's looks; a `--sha` card from another run reads its own run's window, its `hold-out` line saying which look it was. How high the threshold sits at a later look is the planner's answer at a replan, never yours: never re-plan to make a later look pass.
- Paper-stage gates run during paper via `kanso monitor run` (the daemon runs it too), not in `cert run`.
