# Changelog

One line per user-visible change, newest release first. The format is the one
`docs/maintainers.md` §4 and the `kanso-release` skill require; versions are semver.

## Unreleased

- **Bytes already carded are not an experiment.** A proposal that reproduces a file the hypothesis has carded under the run's pins (hypothesis file, snapshot, criteria) is refused on the retry ladder with the card it repeats, instead of being backtested again and counted as another trial; one sleeve had the same sha carded five times in a day. The proposer now sees the last `context_cards` cards of the hypothesis across runs, so a run that begins after a stall is not shown a blank slate. The mock protocol puts the ordinal of the call wherever a script writes `{{call}}`, so a wrapped script can still propose new bytes; the demo run a second time exits 2 naming the cards its answers repeat.

## v0.4.1 — 2026-09-10

- **A stop kills the card in flight.** A card child leads its own session and outlived the lane that supervised it — one ran 70 minutes past a 30-minute budget with weeks to go. `research stop` now interrupts the card, records nothing, and the run resumes at the next start.
- **Two lanes cannot claim one hypothesis.** Lanes poll in step and both read the same head of the queue; the second to remove the row went on to start a run the first lane's run then refused (`already has an active run`, nine times in one workspace) and put the hypothesis back at priority −1 behind a run already in progress. The removal is now the claim: a lane whose delete removed nothing takes the next row.
- **A dead lane no longer loses its hypothesis.** One dequeued between claim and run was left `researching` with neither a run nor a place; the supervisor puts every such hypothesis back in the queue when it starts.
- **Engine fact recorded:** on a NETTING venue closing a position costs the square of the positions closed before it in the other instrument; `doctor` measures it and the intraday program says turnover is what a card's budget buys.
- **A sleeve certified again composes its strategy's next version.** Version n+1 with `attached: []`, pins and expectation from the new certificate; the paper stage replaces the version it holds and retires it, and a construct attached to the old version stays there until it certifies against the new one. Measured in a live workspace: three `deploy_blocked` escalations on four passing certificates of one sleeve, each "a sleeve composes a new strategy at version 1, but sox_main already has 1". The same bytes under the same engine still return the version they have, whatever its position; under a new engine they compose a new one, which is what `deploy`'s own remedy always said.
- **A sized subject composes.** 0.4.0 handed every sized hypothesis's budget to its construct as a parameter, and every construct refused it as undeclared, so no sleeve or overlay under a `sizing` rule could compose; a sleeve's budget is read from its hypothesis and an overlay's travels in its attached ref.
- **A construct composes onto the host it was measured against.** When the host's latest sleeve is not the sleeve of the version the construct's run pinned, composition refuses with a `deploy_blocked` escalation naming both, and the construct's next run pins the new version.
- **A certificate composes under the scope it was earned in.** One whose run pinned a hypothesis of another universe, resolution, data requirement, construct or sizing rule than the one registered now is refused by the field that moved.

## v0.4.0 — 2026-09-10

- **A multi-instrument instant is one book.** Points that share a `ts_init` and a grain are applied to the venue before any author handler of that grain runs; each handler then runs with that book and the fills of the handler before it. A market submitted into another instrument of the instant fills at that instant's close, not the previous one. A limit placed in that handler sees only the close. An incomplete instant still trades the silent leg at the last public price. Data an author raises inside a handler dispatches at once and never takes a cohort's marker.
- **An overlay has its own clock.** `evaluate` runs once inside every host entry (`scale`, and legs beside that order). `on_data` runs once per cohort of the overlay's grain, after every handler of that cohort and never while a market order of the sleeve is unfilled, and places legs without waiting for the next host buy. When the overlay's resolution is finer than the host's, the runner loads both grains for the combined run and the host-alone run alike; the host's `on_bar` still runs only on its grain, and its orders fill on the finer book. `HookContext` gains `book` (the host's own signed position per name), `prices` (the last print of every name at the finest grain loaded) and `clips`.
- **The two code paths agree on what is in flight.** The sleeve reads its own market orders through `Order.is_closed` rather than the cache's status indexes, which answer differently on a node and in a backtest; `kanso replay parity` holds again with an overlay on the host grain.
- **A hypothesis can size every order itself.** `sizing: {mode: full_book, budget: N}` is a top-level, operator-owned key of `hypothesis.yaml` and part of the scope a `best` is comparable under. Under it the harness sizes every entry to the whole budget in one instrument at market (the round trip and one price increment reserved), holds one instrument at a time, exits whole, and `submit_entry`/`submit_exit` take no size; `self.held(id)` is the position reader. A proposal that names a size, builds an order by hand, reads `self.portfolio` or overrides a harness method is discarded by `strategy_integrity` before any backtest, with the line and what to write instead; what the scan cannot see is refused in the handler, the run stops, and the card is a `discard` carrying a `sizing` gate with the rule, the instrument, the instant and the book held. `position_size` under the rule judges entry fills over the budget, gathered per order. `kanso hyp validate` refuses a budget the ceilings cannot fund, a rule on a filter or an exit, a budgeted overlay on an unbudgeted host or the reverse, and a filter or exit rule at a grain that is not its host's.
- **A sized overlay names clips.** `Decision(clips=(Clip(instrument, side),))` — `BUY`, `SELL` or `FLAT` — and the harness sizes each to the overlay's own budget, one clip at a time; `Hedge` is refused on a sized overlay and `Clip` on one without a budget. A ledger over the clip orders keeps the host's own share and the overlay's clips apart even in one name.
- **A composed version carries its budgets and its overlays' grain.** The manifest's sleeve config records `sizing_budget` and `extra_resolutions`, composition measures a version at the largest book any sized part declares, and a stage node and a `--strategy` replay load what a card did (`docs/backlog.md` row 64 closed). `deploy` blocks a share below a version's budgets with a `deploy_blocked` escalation.
- **Engine facts recorded** (`nautilus/facts.py`): an order is open from `INITIALIZED` until a terminal event; the exchange matches against the finest bar type it has seen; a market order past a quarter of a bar's volume walks one increment for the rest.

## v0.3.0 — 2026-09-08

- **A hypothesis can say what a position is worth, and a model cannot talk it down.** `required_constraints` is a fourth top-level key in `hypothesis.yaml`, holding card-stage gates the operator requires. Classification owns three keys of that file and this is not one of them, so it survives a re-classification with comments and ordering intact; both lists are evaluated on every card, the operator's first, and where both name a gate the operator's entry stands and the classifier's is dropped. Naming one twice is refused (exit 3). A draft may carry it.
- `position_size {min_pct, max_pct}` is a fourth card-stage gate, and the only one in the package that carries a **floor**. `risk_limits` are three ceilings, so a strategy holding a tenth of what its hypothesis asked for satisfied every one of them and nothing could say otherwise — measured in a live workspace, a sleeve briefed for \$10,000 positions sized a flat \$3,000 — `capital * 0.3` — and passed every limit it had.
- A run records what it held. `CardRun.held` is what each instrument was worth at each period end, marked at that period's price — the equity curve already computed it per instrument and summed it away. It is the only quantity in a run that answers what a position was worth while it was open: `Fill.notional` is traded value struck at one price, and `Trade.notional` is an opening cost basis, biased upward by a strategy that rebalances toward a target as price falls and blind to the drift of one entered once and left alone.
- For a construct attached to a host, `position_size` subtracts the host's quantity and re-marks the remainder, so a modifier is judged on what it added rather than on what its host holds.
- Docs: `docs/concepts.md` gains a `What a card must satisfy` section listing the four card-stage gates and why the new one is measured where it is; `docs/workspace.md` documents `required_constraints` and shows one.

## v0.2.0 — 2026-09-08

- **A hypothesis is never ended by kanso.** `n_fail` consecutive failing certificates used to write the status `failed`, which the queue treated as terminal — `dequeue` dropped it on sight, `enqueue` refused it, and the remedy printed was to register the idea again under a new id, which resets the trial count `deflated_sharpe` prices the search width by. A failing verdict now returns the hypothesis to `researching` every time and escalates on every `n_fail`-th failure. Ending a line of research is the operator's decision and `kanso hyp retire` is the whole of it.
- `kanso hyp resume ID` is the inverse `retire` never had: it takes a retired hypothesis, or one an older kanso turned `failed`, back to `researching` and clears its consecutive-failure count. `kanso research queue add ID` then gives it a lane. Refused (exit 2) on a hypothesis research has not ended.
- A retired hypothesis stays retired. A certification that began before the retire ended by returning its subject to `researching`, so an operator's own ending could be undone by work already in flight; `set_status` now refuses to move one and `on_stall` checks the retire on both sides of the certification it runs.
- **The proposer is handed the ids of the gates a certification failed, and never their evidence.** `embargoed_window` and `walk_forward_consistency` both record the objective's value over the certification window, and the proposer writes the next `strategy.py`, so that dict was a route from the embargoed window into research — arriving as feedback rather than as a backtest request. Measured in a live workspace: 79 of one hypothesis's 356 cards were proposed while a certification-window figure and its four fold values stood in the prompt.
- A drift verdict no longer marks a run's baseline card. A check judges what the loop proposed, and no model proposed the bytes a run was handed. Marking it left a rewound run with no aligned keep to fall back on, so `_revert` cleared the best and the next card that passed its constraints kept at any metric: measured, a hypothesis's best fell from 5.3976 to 5.0256 twenty-three seconds after a drift, and the certificate minted on the worse strategy is what ended it. Reachable only when a run's *first* check drifted.
- Docs: `docs/concepts.md` states the lifecycle with `retired` as its one end and says why gate ids travel without their evidence; `docs/cli.md` gains `kanso hyp resume` and corrects the queue rule in both places it appears; the `kanso-research` skill and the `kanso.toml` template no longer say a hypothesis dies of `n_fail`; `docs/backlog.md` rows 61, 62 and 63 record the drift rewind's remaining cross-run case, the absence of any bound on how long one hypothesis holds a lane, and the gate-evidence partition that would give the proposer its detail back safely.

- kanso applies a split rather than trading through it. An equity declares the splits it has been through in its own definition — `override.info.splits: [{ex_date, ratio}]` in `instruments.yaml` — and the simulated venue applies each one at its ex-date: on the first market point whose reference time reaches it, and one call before that point is matched against anything, every resting order in the instrument is cancelled, every open position is rescaled and the portfolio index is resynced behind the change. Measured before this: a 1,005-share position at ten dollars through a one-for-ten reverse split closed as a realised 90,450 and a final equity of 190,450 against a true 99,950, and the exit was sized against 1,005 shares that no longer existed.
- It is the venue and not the strategy because a strategy is a bar too late. A sleeve handles a point only after the exchange has matched against it — `BacktestEngine` processes every point through the venue before the data engine publishes it, and a node subscribes its venue above a strategy's priority — so a take-profit resting at fifty was filled for 1,005 shares on the ex-date bar of a reverse split that restated the price to a hundred: 40,169.85 of profit on a bookkeeping change, from the most ordinary exit there is. Cancelling standing orders across a corporate action is a broker's job in any case, so a deployment against a real broker loads none of this, and both simulated venues load the same module — which is what lets `kanso replay parity` compare the two code paths across a split at a tolerance of zero.
- A card's own numbers are split-aware. The equity curve folds the quantity change in at the ex-date, reading it off the position's own adjustment ledger rather than recomputing it from a ratio; a trade's size, its two average prices and its profit are computed from its fills and that ledger instead of from `peak_qty`, `avg_px_open` and `realized_pnl`, which the engine leaves in the share count the position opened in. `notional` is still what was put in, and the only profit or loss a split itself produces is the fractional residue a reverse split truncates away — 50 dollars on the position above. With no split anywhere the arithmetic reproduces the engine's own numbers exactly, so there is one definition of a trade and not two.
- A run whose window holds a split its instrument does not schedule is refused (exit 2), naming the instrument, the ex-date and the ratio, with the entry to write. The refusal is made in the parent process, before a card's child exists, so it is a message an operator reads rather than a crash the run records; a schedule that names a different ratio for that day is refused too, since a schedule contradicting the data is worse than none. Its reach depends on the data: a corporate-actions dataset whose points carry the day each action was announced is snapshot-covered and its splits reach the check, while one that has only effective dates declares no publication instant and is refused a snapshot already. A workspace that loads no corporate actions has told kanso nothing, and kanso invents nothing.
- A position a reverse split would leave under one lot is refused rather than silently deleted, naming the instrument, the holding and the ratio: kanso holds no cash to pay a fractional position out in lieu, and a schedule carries no cash for the same reason money moves in only one place — the runner's extraction, once per fill. A `cash` key in a schedule entry is refused by name (exit 3) with a pointer to the `corporate_action` data type, which carries the announcement date a dividend has and a split does not.
- `strategy_integrity` denies a researched `strategy.py` the route to the split schedule and everything the engine derives from a position's opening basis, and says why in the refusal. `.cache` is the only way a strategy can hold an instrument, and an instrument names every split of its life including ones after the window a card is judged on; `avg_px_open` survives a split unrescaled, so the account, `peak_qty`, `realized_pnl`, `realized_return`, `equity` and the portfolio's P&L views are denied with it — measured under kanso's own venue, a 100,000 account read 109,000 and the position reported a 9,000 profit on a 50 loss once it closed. `program.md` lists the denials for the author, and a card's failing gates and their evidence now reach the next proposal, so a discard before any backtest ran no longer arrives as a metric with no reason.
- `kanso doctor` re-checks three more engine bindings against the installed `nautilus_trader`: that a position adjustment changes the quantity and leaves the fills, the commissions and the opening basis alone; that `Portfolio.initialize_positions` exists where the read-only facade does not declare it; and that a simulation module is handed every market point before the venue matches against it.
- Docs: `docs/workspace.md` documents the schedule, its ratio convention, the resolve-and-re-snapshot it needs and why it lives on the definition rather than in the data; `docs/concepts.md` gains a `Corporate actions` section, states the two integrity denials and shows the refusal as it was run; `docs/cli.md` records it against `research card` and `research begin`; `docs/backlog.md` row 60 records that cash corporate actions are still not applied, and why the line is drawn where it is.

## v0.1.2 — 2026-09-07

- The parameter map `kanso classify` and `kanso cert plan` ask a model for is a shape a provider will accept. Both declared theirs as a free-form `{"type": "object"}`, and the Anthropic messages API refuses that document outright — `400 output_config.format.schema: For 'object' type, 'additionalProperties' must be explicitly set to false`, measured on 2026-09-07, one request per candidate shape. A gate's and a construct's parameters now travel as a list of `{name, value}` pairs, the one shape measured both to be accepted **and** to come back filled in; the obvious repair, a closed object with no properties, is accepted and answers `params: {}`, dropping every parameter the model chose. kanso reads the pairs back into a mapping before any step sees them, so a classification, a plan and every gate hold what they always held.
- What that cost a workspace on the `anthropic` protocol: `classify` and `cert plan` are the first two steps of the pipeline, and both were refused on every call, in every workspace, for the life of 0.1.1. What was measured then is the parameter shape; that it was the *only* thing wrong with those two documents was an inference from a refusal that named only it, and sending the corrected documents disproved it — the next entry is what came back. `propose` and `align_check` carry no parameter map and answered 200 before and after. The `mock` protocol, which is what the demo and the suite drive, never had the problem — which is why nothing offline saw it.
- The same shape is admissible on the `openai_compat` wire, whose structured outputs impose the `additionalProperties: false` rule too. That is read from the protocol, not measured: no request from that client has been sent to a server that speaks it. It has a second requirement — every property listed in `required` — which `classify` does not meet, and `docs/backlog.md` row 57 holds that half open.
- A model that names one parameter twice is asked again with the name in the complaint, rather than kanso deciding which of the two values it meant. The retry is the router's ordinary ladder; nothing is repaired silently.
- `mock/responses.yaml` writes every `params` as that same list of pairs, because it is what a real model answers with. A hand-written script that still uses a map is rejected as a wrong answer by the schema check and takes the ladder, so the fix is to rewrite the entry rather than to debug the refusal.
- The `kanso classify` schema asks for its keep rule without a numeric bound, because a numeric bound is a keyword the provider refuses. With the parameter map corrected, `certify_plan`, `propose` and `align_check` were answered 200 with the schemas as shipped and `classify` was answered 400 a second time — `output_config.format.schema: For 'number' type, property 'minimum' is not supported` — for the `minimum: 0` on `min_delta` and `k_se`. Measured on 2026-09-07, one request per keyword: `minimum` and `exclusiveMinimum` are refused on `number` and on `integer` alike, while `minLength`, `maxLength`, `enum`, `pattern`, `minItems` and `description` are all accepted. Both bounds are off the wire, stated in the instruction instead, and enforced where they always were.
- A keep rule outside those bounds is refused by name. A model answering `k_se: 0` is now told `objective.params.k_se: Input should be greater than 0` and asked again. It was already told which field and which bound — `the answer is not a classification: k_se: Input should be greater than 0` — and what changed is that the complaint now locates the field in the answer document, the shape a value outside the toolbox's range already earned, and gives each field its own line rather than one joined sentence. The wire no longer states that bound at all, which makes what the refusal says the whole of what the next attempt has to go on.
- What kanso may send and what kanso can check are two different sets, and only one of them is a property of this package. `models/jsonschema.py` declares `ADMISSIBLE` — the keywords a provider was measured to accept, with the measurement and its date written beside them — next to the `VOCABULARY` its own checker reads, and the suite now holds every node of every shipped schema to each set separately. Neither contains the other, which is why the guard that shipped with the entries above could not have caught this: `minimum` is in the vocabulary.
- Docs: `docs/workspace.md` says what shape a scripted `params` takes, in both places it describes `mock/responses.yaml`.

- `kanso inbox` pads the kind column past the longest kind, so a `deploy_blocked` entry no longer runs into its subject.
- `kanso init` renders a commented `[data]` table (`reference`, `adjusted`) and an `[adapters.<id>]` hint into `kanso.toml`, so the rendered file is the reference for every key the parser reads; the header is commented too, so a `[data]` table you append is not declared twice.

## v0.1.0 — 2026-09-06

First release.

- `kanso doctor` grades a state database written by a later kanso as a failure rather than reporting it up to date, so it no longer disagrees with every other command about whether a workspace is usable.
- `kanso data sync` extends only the **newest** dataset of each series, so a series with a chunked backfill behind it can be continued at all; `--dataset` still names one directly, newest of its series or not.
- `kanso data instruments resolve` builds the `[data] reference` adapter only once an id is actually left unresolved, so a wholly manual universe resolves with that adapter's credential unset.
- A baseline that did not run reports the remedy of the failure that ended it — rows the catalog no longer holds send an operator to `kanso data load` — where every cause alike used to say `fix hypotheses/<id>/strategy.py`.
- `kanso hyp validate` and `kanso hyp add` refuse a construct parameter the construct does not declare, or a value outside its declared set (exit 3); the refusal used to arrive inside a run's first card.
- `kanso hyp validate` and `kanso hyp add` refuse `portfolio` as a hypothesis id (exit 3): it is how a construct attached to the book names its host.
- `kanso portfolio deploy` and `kanso replay run --strategy` hash every file under `strategies/<id>/impl/<version>/` against the `strategy_sha` its manifest records, and refuse an edited, truncated or deleted source by name (exit 3), naming the certified copy to restore it from.
- `kanso portfolio show` reads `portfolio.yaml` against the record: a stage entry no deployment wrote prints as `not deployed · in portfolio.yaml only`, carries `"recorded": false` under `--json`, and counts towards neither the stage's allocation nor its P&L nor whether its node is up.
- `kanso cert plan` warns when the paper window the plan implies is under a tenth of the certification window the hypothesis declares, and pins the plan either way; `warnings` under `--json`.
- A `kanso_ext` module declaring `gates` or `objectives` in `PROVIDES` is refused where it is declared: no registry reads either kind, and a criterion is written in the package.
- `kanso doctor`'s shadow check reads one registry per kind a declaration may carry — the packaged constructs, the custom data types and the framework's own `sandbox` execution client included — where it read three kinds out of seven.
- `[adapters.alpaca] poll_interval_s` sets the live feed's sweep cadence, `1` to `3600` seconds and still 15 by default, refused out of range when the table is read; it was a constructor argument no workspace could reach.
- `kanso init [--demo]`: a workspace is a plain directory; `--demo` runs end to end with no credential of any kind.
- `kanso doctor [--report] [--check-adapters]`: thirteen checks over the workspace, the install, the engine, the credentials, the adapters, the execution clients and the lanes.
- Data: `data load`, `show`, `snapshot`, `backfill`, `sync`, `instruments resolve|show`, `adapters [--check]`; one catalog, manifests recording the span a source *served*, immutable snapshots.
- Availability: every point carries `ts_init` (public) and `ts_event` (economic), `ts_init >= ts_event`; a delayed dataset with no declared publication rule is refused at write.
- Hypotheses: `hyp new|validate|add|show|retire` and `classify`; a hypothesis is pinned by the sha256 of its bytes and its progress lives in `state.db`.
- Constructs: seven in the catalogue, four runnable — `sleeve`, `filter`, `overlay` on a sleeve, `exit`; `alpha`, `execution` and portfolio-hosted `allocation` classify and refuse at `research begin` naming their seam.
- Research: `research begin|card|run|end|show`, the keep rule with its noise floor and complexity clause, `align check`, and the daemon (`research start|stop|status|queue`).
- The embargo is code: a card runs in a child process with no path to any catalog, and the `strategy_integrity` syntax-tree check runs before the backtest.
- Certification: `cert plan|run|show`; no default plan and no non-LLM fallback, gates chosen at runtime inside the toolbox's declared ranges, certificates immutable and pinned to plan, snapshot and engine version.
- Strategies and the portfolio: `strat compose|show|retire`, `portfolio show|clients|deploy`, `promote --live --as NAME`, `demote`, `monitor run`; one generated `impl/<version>/` loaded by backtest, replay and node alike.
- Real capital moves only on a named, recorded approval; `deploy` refuses six things with exit 2 and two with exit 4.
- Replay: `replay run|parity|show`, comparing the live and research code paths element by element at a tolerance meant to be zero.
- Models: `models check`, a register routed by task class and tier, every call ledgered including a retry's failed attempts.
- Operating: `status`, `inbox [ack]`, `migrate`, `skills sync`, `env detect`, `ext show`.
- Adapters: one first-party data vendor and one first-party broker, both enabled by their credentials and never by installation; the core knows neither.
- Extensions: `kanso_ext/` provides loaders, constructs, custom data types, data adapters and execution clients; a packaged id always wins.
- Eleven operator skills and the workspace templates ship inside the wheel.
